# Реферальная система ScoreGame — v1 (2026-07-14)

Статус: **РЕАЛИЗОВАНО** (миграция 0125; лестница наград утверждена 2026-07-14, economy-v1 §21 обновлён). Не задеплоено — деплой: сначала `wrangler d1 migrations apply scoregame_db`, затем api-worker + web/front-worker.

Реализация: `api-worker/src/referral.ts` (чистые хелперы: коды, валидация конфига) + блок в `index.ts` (`processReferralActivation`, роуты `/referral/claim`, `/referrals`, `/admin/economy/referral/{config,stats}`), фронт `web/app/components/ReferralCard.tsx` + баннер на главной + кнопка меню, админка — секция «Реферальная программа» во вкладке Экономика. Тесты: `referral.test.ts` (13 юнит) + `referralActivation.inttest.ts` (8 инт. на живой D1).

Отличия реализации от первоначального наброска:
- **Награды (утверждено)**: приглашённому — Фартовый жетон (не Daily), пригласившему — Daily за друга, рубежи 3 → Premium, 5 → жетон, 10 → Premium. Конфиг редактируется в админке (app_config `referral_config`), дефолты в коде.
- Кап — скользящие 24 часа (не календарные сутки): проще и без МСК-подводных камней; сверх капа награда реферера откладывается и досыпается при следующей активации любого друга (welcome-награда приглашённого выдаётся сразу в любом случае).
- Баннер на главной статичный (ноль API-запросов, текст = дефолтные награды), скрывается крестиком (localStorage). Персональная ссылка строится на клиенте (base36 от id) — API при шаринге не участвует.
- Уведомление рефереру шлёт api-worker напрямую (`telegramBotApi`, plain text), не bot-worker.

## Принцип

Ноль крона, ноль новых таблиц, ноль чтений в горячем пути. Вся система = 3 колонки в `users` + inline-хук в сохранении пика + существующий reward_ledger.

## Механика

1. **Код реферера не хранится** — вычисляется из telegram id (реверсивный base36, тот же механизм, что `profile_key`). Ссылка: `t.me/scoregameee_Bot?startapp=ref_<code>`.
2. **Привязка** — `start_param` приходит внутри HMAC-подписанного initData. Только при INSERT нового юзера: `users.referred_by = <id>`. Самоприглашение (code == own id) молча игнорируется. Существующим юзерам ссылка ничего не делает.
3. **Активация** — хук в хендлере сохранения пика: если `referred_by IS NOT NULL AND referral_rewarded_at IS NULL` (поля уже загруженной строки юзера — лишних чтений нет) → награды обоим через ledger, `operation_id = referral:<invitee_id>` (идемпотентность бесплатно).
4. **Атрибуция каналов** тем же парсером: `startapp=src_<канал>` → `users.acquired_via` (write-once при регистрации). Аналитика — запрос в админке по требованию.

## Награды (кейсами, НЕ звёздами и НЕ мячами напрямую)

| Кому | Что |
|---|---|
| Приглашённый (за первый пик) | 1 Daily case |
| Пригласивший (за каждого активированного) | 1 Daily case |
| Milestone: 3-й и 10-й активированный друг | Premium case |

Обоснование: не ломает недельную эмиссию звёзд (§23 economy-v1), не откатывает удаление звёзд из кейсов (0124), мячи — дорогая валюта, линейная выдача = дыра.

## Антифрод

- Награда за активацию (первый сохранённый пик), не за клик/регистрацию.
- Кап: 10 награждаемых рефералов/сутки на реферера (COUNT по индексу `referred_by` — только в момент активации). Друзья сверх капа остаются «ожидающими», награда догоняется при следующей активации в другой день.
- Стоимость атаки: живой TG-аккаунт (телефон) + пик; приз — Daily case. Экономически бессмысленно.

## UX

**Пригласивший** — блок в профиле (источник правды):
- Правила одной строкой: «Друг получит Daily-кейс за первый прогноз. Ты — Daily-кейс за каждого друга, Premium за 3-го и 10-го».
- Три состояния: «Ожидают первого прогноза: N» / «Активировано: N» / прогресс до milestone.
- Бот-уведомление при активации: «Твой друг Имя сделал первый прогноз — держи Daily-кейс 🎁».

**Приглашённый:**
- При первом входе: тост «Тебя пригласил Имя. Сделай первый прогноз — получишь Daily-кейс».
- После первого пика: синхронный тост «Daily-кейс получен 🎁» (награда в том же ответе сервера).

**Точки входа (НЕ отдельный раздел в навигации):**
1. Баннер на главной «Пригласи друга, получите по кейсу 🎁» → реферальный блок; показывать пока < 3 активированных друзей, затем сворачивать в компактную строку.
2. Профильный блок — постоянный дом механики.
3. Позже (август, вместе с «Поделиться результатом»): CTA «Позови друга» на экране угаданного счёта.

**Не-события без ошибок:** переход существующего юзера по ссылке, самоприглашение — молча ничего.

## Не делаем в v1

- Отдельный раздел «Рефералы/Друзья» в навигации (мёртвая вкладка ради одной кнопки; пересмотреть при низкой конверсии share).
- Интеграция в квест-движок (`checkDailyQuests`) — реферала не повторяемое действие, ломает модель ресетов и мотивирует фрод. Максимум — статичная карточка в разделе заданий, ссылающаяся на реферальный блок (после запуска, по метрикам).
- Звёзды/мячи как награда.

## Реализация (оценка)

- Миграция: `users.referred_by`, `users.referral_rewarded_at`, `users.acquired_via` + индекс по `referred_by`.
- api-worker: парсинг `ref_`/`src_` в auth-пути, хук в pick-save, счётчики в ответе профиля, строка в /admin/stats.
- bot-worker: одно уведомление при активации.
- web: блок в профиле, баннер на главной, тосты.
- Объём: ~день работы с тестами. D1-стоимость: 1–2 write на регистрацию, 2–4 write на активацию, ноль в горячем пути.
